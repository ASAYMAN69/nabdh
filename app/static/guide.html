Data guide

Format your data so the tool can read it

A clean CSV is the difference between a useful screening list and a list full of warnings. This page gives you the exact columns, accepted values, units, and fixes for the most common mistakes. No technical background needed.

Quick start

A CSV is just a table saved as text. You can make one in Excel or Google Sheets. The tool requires two columns: age and sex. We strongly recommend a third: id.

1

Put column names in row 1

id, age, sex, then any optional columns.

2

One person per row

No merged cells, no totals, no blank rows, no title rows.

3

Save as CSV UTF-8

In Excel: Save As → CSV UTF-8 (Comma delimited).

Tip: the full template already contains every standard column the tool reads. Delete the example rows and any columns you do not need. Blank cells are fine.

Required and recommended columns

ColumnRequired?What to putExample
id Recommended A study or clinic ID. If missing, the tool uses the row number and you cannot link a result back to a person. Do not use names or Emirates ID. EX-001
age Required Age in years, 0–120. Missing or impossible values are flagged, not guessed. 45
sex Required Safest: male or female. Also accepted: m/f, 0/1, 1/2. female
pregnant Complete if relevant yes or no for every woman who may be pregnant. Pregnancy changes the pathway. Leave blank for men. no

Sex coding — read this once

Sex can be text or numbers. Use one convention for the whole file. The safest choice is the word male or female.

Ambiguous file: a column containing only 1s is read as 1 = female. If all the people in your file are male and your system codes male as 1, use the word male, or rename the column to riagendr and upload again. Mixing 0 and 2 in one file is also unsafe.

Three unit traps that can hurt

D-dimer: many labs report µg/mL FEU. If you enter 0.5 into d_dimer, it is marked unit-suspect and is not escalated. Use d_dimer_ug_ml or convert to ng/mL FEU.
LVEF: a fraction such as 0.45 entered into lvef_pct is marked unit-suspect and is not escalated. Use lvef_fraction or enter 45.
Assay names matter: the tool reads troponin I and NT-proBNP. It does not distinguish troponin T from troponin I, or BNP from NT-proBNP. Do not put a different assay in these columns; leave it blank or use a column the tool recognises.
Do not type units in cells. Write 126, not 126 mg/dL. A cell with text is treated as missing.

After you upload

  • The tool reads the file and shows a Cohort Summary.
  • Warnings appear at the top of the results in plain language.
  • A row with missing age or sex is marked Insufficient data. It is not treated as normal.
  • If one lab has an ambiguous unit, only that lab is excluded. The person's other results are still used. The summary shows Results not checked. Correct the unit and upload again.
  • Small groups are hidden in the privacy report.
  • Click any row to see why the person was flagged, what was captured, and the recommended pathway.
If the file has no lab results or BP: the tool can still order the list, but it has checked nothing that could be urgent. The absence of urgent rows means “not checked”, not “normal”.

Safety notes

Unit-suspect urgent labs

If a troponin, D-dimer, or NT-proBNP is in an urgent range but the unit is missing or ambiguous, it will not make the person Urgent. The row may look routine. Treat that result as unreviewed and follow it up manually; the tier is not reassurance.

Tests the tool does not read

The tool does not apply clinical rules to creatinine, potassium, sodium, INR, urine albumin/ACR, ALT/AST, bilirubin, TSH, haemoglobin, or ECG/QTc. BNP and troponin T are also not read. A blank column does not mean “normal”; it may mean “not read”.

Dates and treatment status

The tool does not read measurement dates or know whether a raised BP is already treated. Use the screening-history yes/no columns, and record the diagnosis accurately.

Small groups

Groups with fewer than 10 adults are hidden, with complementary suppression to prevent subtraction. This protects privacy; it does not change the person's own result.

This is a demonstration prototype. It is not a medical device and must not be used for diagnosis or treatment without local validation, regulatory review, and clinician sign-off.

For developers

The app is a same-origin FastAPI service. Scoring is deterministic and makes no external calls. Upload a CSV with multipart/form-data; the field name is file.

EndpointPurpose
GET /healthService health and version.
POST /api/scoreScore a CSV and return ranked JSON.
POST /api/score.csvDownload the ranked list as a sanitised CSV.
GET /api/outcomesRead the local outcome tracker.
POST /api/outcomesRecord a simulated outreach choice or completion.
GET /clinician_template.csvDownload the full template.

Example

curl -s http://127.0.0.1:8000/health

curl -s -X POST http://127.0.0.1:8000/api/score \
  -F "file=@clinician_template.csv;type=text/csv"

Limits and formats

  • CSV, UTF-8. Comma is safest; semicolons, tabs, and | are also read.
  • Maximum 200,000 rows, 1,000 columns, 64 MB.
  • Aliases are accepted for common column names (gender → sex, sbp → systolic_bp, a1c → hba1c).
  • CSV export neutralises leading = + - @ to prevent spreadsheet formula injection.
  • The demo has no authentication, TLS, or multi-user isolation. Do not deploy it with real patient data.
